# 设计规范

页面视觉与交互的约定，改动时请遵循，保持一致性。所有值均来自 `src/index.html` 的 `<style>` 段。

---

## 1. 配色体系（莫兰迪绿 + 金）

CSS 变量定义在 `:root`：

| 变量 | 值 | 用途 |
|---|---|---|
| `--dark` | `#214E3B` | 主深绿：header、表头、主按钮、KPI 数值 |
| `--green` | `#376B55` | 中绿：已付款、渐变、hover |
| `--gold` | `#C79A52` | 金：强调色、预算款、KPI 顶条、回到顶部按钮 |
| `--red` | `#C95252` | 红：删除等危险操作 |
| `--bg` | `#F4F7F5` | 页面浅绿灰背景 |
| `--card` | `#FFFFFF` | 卡片白 |
| `--line` | `#E3EAE5` | 分隔线/边框 |
| `--ink` | `#24312B` | 正文墨色 |
| `--muted` | `#6D7771` | 次要文字 |
| `--paid-bg` | `#E5F3E9` | 已付款浅底 |
| `--budget-bg`| `#FBF7EF` | 预算款浅底 |
| `--unpaid-bg`| `#FCE8E6` | 警示浅底 |

**回款节点专属配色**（区别于普通阶段）：金棕渐变 `#7A5B12 → #A97E22 → #C79A52`，表头 `#8A6A1C`，金额字 `#A97112`。

**语义色**：预算=金，已付=绿，省下=蓝，危险操作=红；状态徽章「已完成」绿底(`#C6EFCE`/`#227A3D`)、「未完成」橙底(`#FFE7C2`/`#B9600F`)。

---

## 2. 字体与排版

- 字体栈：`"PingFang SC","Microsoft YaHei",-apple-system,sans-serif`（中文优先，跨 Mac/Win）。
- 金额统一 `font-variant-numeric: tabular-nums`（等宽数字对齐），右对齐。
- 金额格式：`toLocaleString('zh-CN',{maximumFractionDigits:2})`，KPI 金额值前加 `¥` 前缀符。
- 层级：h1 26px / KPI 值 22px / 阶段标题 16px / 正文 13-14px / 表格 13px / 次要 11-12px。

---

## 3. 布局约定

- **统一容器**：主要区块 `max-width:1280px; margin:auto; padding:0 24px` 居中对齐。
- **KPI 网格**：桌面 6 列，`@900px` 3 列，`@600px` 2 列。
- **图表区**：桌面 `2fr 1fr`（条形图宽、环形图窄），`@900px` 单列堆叠。
- **表格**：金额列表头右对齐（`.thmoney`），状态列表头居中（`.thcenter`）；单元格与表头 padding 对齐（首列 22px、金额列右 22px），解决历史「表头与数据不对齐」问题。
- **移动端**（`@600px`）：表格 `overflow-x:auto` 横向滚动**保留所有列**（不删列）、`min-width:680px`；触摸友好放大点击区；悬浮按钮 52px。

---

## 4. 动效约定

**两套动效并存**：

1. **CSS 动画**（无依赖降级）：header 光晕 `float`、标题 `slideDown`、KPI `pop` 交错、阶段 `rise`、单元格保存 `flash`、进度条宽度过渡。
2. **anime.js v3.2.2**（内联，`window.anime` 存在时增强）：
   - KPI 卡片弹入：`translateY+scale`，`stagger(80)`，`easeOutBack`
   - 阶段进场：阶段头 `translateY`、行 `translateX` 交错 `stagger(28)`，`easeOutCubic`
   - 状态切换：徽章 `scale` 弹跳 `easeOutBack`
   - 回到流程开始：目标阶段 `scale` 弹性 `easeOutElastic`

**数字增量动画**：KPI 数值用自写 `animateNumber`（rAF + ease-out-cubic，700ms），从旧值滚动到新值；金额过程中格式化。**注意**：不做整体重渲染，避免动画被打断。

**图表进场**：`drawCharts()` 用 rAF 播放 900ms `ease-out-cubic`，条形/环形从 0 生长。

> 降级原则：anime.js 全部包在 `if(window.anime)` 内，缺失时页面仍可用（退回 CSS 动画）。

---

## 5. 交互约定

- **编辑**：点单元格 `contenteditable`，blur 或 Enter 保存；金额自动清洗 `, ¥ 空格` 并重新格式化；保存后单元格 `flash` 绿闪 + toast「已保存 ✓」。
- **状态切换**：点状态徽章在「已完成 / 未完成」间切换，即时保存 + 重算 KPI。
- **筛选**：chip 三选一（全部/已完成/未完成）+ 搜索框（匹配 类别/空间/名称/品牌/备注）。
- **折叠**：点阶段头折叠/展开该阶段（点单元格不触发）；工具条「展开/收起全部」批量切换。
- **反馈统一走 toast**（底部居中胶囊，1.6s 自动消失）；破坏性操作（恢复初始/导入覆盖）用 `confirm` 二次确认。
- **悬浮按钮**：滚动 >400px 出现；`↑` 回顶（金色）、`⚑` 回到流程开始（深绿），hover 显示文字提示（触摸设备隐藏提示）。

## 6. 一致性检查清单（改动后自检）

- [ ] 新增金额列是否带 `money` class（右对齐 + tabular-nums + 格式化）？
- [ ] 新颜色是否复用 `:root` 变量而非硬编码？
- [ ] 新动效是否包在 `if(window.anime)` 内、并有 CSS 降级？
- [ ] 移动端断点（900 / 600）下是否仍可用、不溢出？
- [ ] 破坏性操作是否有 `confirm`？操作反馈是否走 toast？
