# 需求与演进历史

本文件记录这个页面从「Excel 分析」到「v6 网页」的完整需求脉络，帮助接手者理解**每一处设计为什么存在**。

---

## 阶段 0：源头 —— 一份 Excel 预算表

项目起点是一个 Excel 文件：`雍贤山庐7-1004装修预算总表-阶段末统计版.xlsx`（127㎡ 毛坯房装修预算，WPS 导出）。

- 先做了**只读分析**（不改原文件），识别出 9 类问题：西文字体导致中文回退、冻结窗格位置错误(A98)、金额精度冗余、空值/0 语义不清、完成状态无视觉编码、边框断裂、阶段编号跳号、KPI 空壳、备注列承载结构化信息。
- 随后在**副本**上做了 xlsx 优化、图表重构、顶部 KPI 重构等多轮迭代。

> 技术注记：该 xlsx 由 WPS 导出，内嵌图表 `grouping="none"` 是非标准值，标准 openpyxl 直接 `load_workbook` 会报错，需先剥离图表属性。

**顶部 KPI 的最终定义**（从 Excel 阶段就定下，沿用到网页）：

| KPI | 含义 | 计算 |
|---|---|---|
| 总预算 | 所有预算款之和 | ΣF（各阶段预算款） |
| 已付款 | 所有已付之和 | ΣG |
| 未付尾款 | 所有未付之和 | ΣH |
| 预计剩余未付 | 总预算 − 已付款 | 总预算 − 已付 |
| 已完成节点 | 状态=已完成的条目数 | COUNTIF(状态,"已完成") |
| 未完成节点 | 状态=未完成的条目数 | COUNTIF(状态,"未完成") |

## 阶段 1：转为独立 HTML 页面（v1）

**需求**：基于表格数据生成一个完整独立 HTML 页面，要求：直观展示、单元格实时编辑+自动保存、丰富动画特效、纯 HTML/CSS/JS 无框架、响应式。

**实现要点**：
- 数据内联为 `SEED` 常量，运行时存 localStorage
- 点击单元格 `contenteditable` 编辑，失焦保存
- 6 KPI 卡片 + 阶段分块表格 + 完成进度条
- 搜索、状态筛选、阶段折叠、恢复初始数据

## 阶段 2：视觉与交互增强（v2）

**需求（6 项）**：
1. 修复模块标题渐变白字对比度不足 → 改深色渐变 + 白色胶囊高亮
2. 标题与表头对齐 → 统一 padding
3. 增强视觉（阴影/圆角/过渡/hover）
4. 模块统一对齐（max-width:1280px 居中）
5. 添加数据图表 → 纯 Canvas 自绘条形图 + 环形图
6. 数字增量动画 → 取消整体重渲染，KPI 用 requestAnimationFrame 缓动计数

## 阶段 4：结构化与移动端（v4）

**需求（4 项，其中动效需先确认）**：
1. **回款节点独立逻辑**：不显示预算相关列，只展示回收款 → 专属 5 列（回款项目/空间/回收金额/日期/备注）+ 金棕配色区分 + "回收合计"汇总
2. **快速返回头节点按钮** → 新增「回到流程开始」悬浮按钮（⚑），与「回到顶部」（↑）组成按钮组
3. **移动端适配** → KPI 2 列、表格横向滚动保留全列、触摸友好点击区、工具条换行
4. **集成动效库**（先描述确认再加）→ 调研后选定 **Anime.js**（GitHub star 最高的无框架 JS 动效库，66K stars，MIT），**内联离线**引入。用于 KPI 弹入、阶段交错进场、状态切换弹跳

> 决策记录：Motion/Framer Motion、React Spring 是 React 专用不适用；GSAP 偏重且部分特性需授权。故选 Anime.js。

## 贯穿全程的两条铁律（接手必读）

1. **不修改用户原始文件**：所有 Excel 操作都在 `/tmp` 副本上进行，原 xlsx 用 MD5 校验保证零改动。网页也是每次另存新版本号，不覆盖旧文件。
2. **改 SEED 必升 LS_KEY**：否则用户浏览器里的旧 localStorage 会盖掉新数据。这是本项目最高频的坑。
3. **HTML SEED 与 data/*.xlsx、data/budget-seed.json 三者同源**：改数据时三者需保持一致（Excel 可用 `/tmp/gen_budget_xlsx.py` 从 HTML SEED 重新生成）。
